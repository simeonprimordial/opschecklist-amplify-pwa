# OpsChecklist Architecture

## Overview

OpsChecklist is a lightweight React Progressive Web App deployed through AWS Amplify Hosting.

The project demonstrates a Git-driven CI/CD workflow, HTTPS hosting, service-worker-based offline support, and local persistence of checklist data.

## Components

### React

Provides the application interface and checklist functionality.

### GitHub

Acts as the source-control repository and triggers the connected Amplify deployment workflow when changes are pushed to the production branch.

### AWS Amplify Hosting

Builds and hosts the production frontend.

### Service Worker

Provides offline application-shell behavior and caches static resources.

### Cache Storage

Stores resources required for offline application access.

### localStorage

Stores checklist data locally in the browser.

## Deployment Model

The production artifact is generated by Amplify from the GitHub source.

The local `dist/` directory is not committed to the repository.

```text
Git source
    |
    v
Amplify build
    |
    v
dist/
    |
    v
Amplify Hosting
```

## Release Model

Application releases are explicitly versioned.

Example:

```text
v1.0.0
   |
   v
v1.0.1
```

Amplify deployment history provides a recovery mechanism for restoring a previously deployed version.

## Design Decision

The project uses a minimal custom service-worker implementation rather than adding unnecessary runtime dependencies.

This keeps the application focused on the AWS Amplify, CI/CD, PWA, and operational-learning objectives.
